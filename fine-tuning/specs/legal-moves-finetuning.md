# Spec: Stage 1b Fine-Tune — Pieces Plus Legal Moves

**Builds on:** [chess-board-finetuning.md](chess-board-finetuning.md) (stage 1: pieces only)
**Checklist items:** F-6 (criteria set before results), F-4 (same settings), F-7 (run records)
**Created:** 2026-10-24, before any training or results for this version

---

## Goal

The pieces-only fine-tune (batch 1) taught models to list where the pieces are: held-out recall went
from 1–19% to 89–99% (`board_t0_summary.csv`). It did not improve anything else, and it **lowered**
final move legality by 3–41 points.

The fine-tuned models now answer with well-formed but illegal moves, even when the prompt lists the
legal moves (Issue 20: 92 of 100 failures probed). And across all models, only 9.3% of first answers
on combined prompts are legal.

This version asks whether teaching the *rules* closes the gap between knowing where the pieces are
and producing a legal move. Each example's target is the piece list as before, then the side to
move, then **every legal move**:

```
White: King g1, Queen d1, ...
Black: King g8, ...
Side to move: Black
Legal moves: Bb4, Bc5, Be7, Kf8, Nf6, ...
```

Moves are SAN, sorted alphabetically, and generated by python-chess, so the targets are exact.

## Design

- **Same models** as batch 1: llama3.2:3b, gemma3:4b, qwen2.5:7b, mistral:7b and deepseek-r1:7b.
  Tags are `<base>-board-legal-ft`.
- **Same 20,000 positions, in the same order,** as `data/board_dataset.jsonl`. The new dataset is
  built *from* that file (`--from-dataset`), so the held-out 200 are the same positions and the only
  thing that changes between the two versions is the target text. The benchmark FENs are already
  excluded (F-1), and the held-out FENs stay out of training (F-2).
- **Same training settings** as batch 1 (LoRA r=16, α=32, 2 epochs, lr 2e-4, seed 42), except
  `max_seq_length` 768 instead of 512. The longest example is about 414 Llama tokens, and other
  tokenizers produce more; padding doesn't change the content.
- **Same benchmark settings** as the base re-run and the pieces-only run (`config/config_legal_ft.yaml`):
  the same 4,000 positions, six formats and worker. The current worker saves raw replies, so
  **first-answer legality can be measured for this version**. It could not be for pieces-only.
- **Three-way comparison** on the same positions and formats: base (re-run) vs pieces-only vs pieces +
  legal.

## Success criteria (F-6, fixed 2026-10-24 before any results)

Every comparison is against the **base re-run**, on paired (position, format) rows.

| # | Question | Measure | Counts as "yes" when |
|---|---|---|---|
| 0 | Did the training work? | held-out legal-move recall and precision (`verify_legal_moves`), and board recall | mean recall and precision ≥ 0.9 |
| 1 | Does knowing the rules transfer to answering? | first-answer legality on combined prompts (`t2_first_attempt_legal`) | rises ≥ 10 points above base, with non-overlapping 95% CIs |
| 2 | Is the pieces-only legality loss undone? | final legality on move-asking prompts | within 2 points of base, or above it |
| 3 | Does it play better? | blunder rate (clamped CPL ≥ 1000) | falls, with non-overlapping 95% CIs |
| 4 | Does it judge positions better? | T1 Spearman ρ | rises to ≥ 0.10 (base ≤ 0.14 for all five) |

**Interpretation, decided in advance:**
- 0 yes, 1–2 yes, 3–4 no → the models **learned the rules but not chess**. This is evidence for
  pattern matching: knowing which moves are possible doesn't produce good moves.
- 0 yes, 3 or 4 yes → evidence that grounding in the board and the rules **transfers** to playing or
  judging.
- 0 yes, 1–4 no → the knowledge sits in a separate "skill" and isn't used when answering the
  benchmark questions. That is a strong pattern-matching result.
- 0 no → the training didn't take; no conclusion about transfer.

The pieces-only version is judged by criteria 2–4 too, but those were written after its results were
known, and the write-up says so.

## Inputs / Outputs

- `fine-tuning/src/board_state.py`:
  - `legal_moves_san(fen) -> list[str]` (sorted)
  - `fen_to_board_and_legal_description(fen) -> str`
  - `verify_legal_moves(fen, text) -> {recall, precision, missing, extra, found}`, which reads the
    `Legal moves:` line; no line gives recall 0
  - `parse_board_description` ignores the `Legal moves:` line, so board accuracy is unaffected
- `generate_board_dataset.py`:
  - `--task {board, board+legal}` (default `board`)
  - `--from-dataset PATH` rebuilds the targets for the FENs in an existing dataset, keeping their order
  - For `board+legal`, the instruction becomes "… List every piece on the board and its exact square,
    then list every legal move."
- `fine-tuning/config/finetune_config_legal.yaml`: the five models, the dataset
  `data/board_legal_dataset.jsonl`, and the same hyperparameters except `max_seq_length: 768`.
- `config/config_legal_ft.yaml`: the benchmark config, identical to `config_base_rerun.yaml` except
  for the models and output paths (`results/finetuning_experiment/legal_ft/…`).
- `src/utils.py`: `FINE_TUNED_SUFFIXES = ("-board-ft", "-board-legal-ft")`. Both `parse_model_info`
  and the comparison script use `base_model_tag()`.
- `fine-tuning/scripts/run_batch.sh`: honours `FT_CONFIG` (default: the batch-1 config) for train,
  import and verify.

## Edge cases

| Case | Behaviour |
|---|---|
| A position with no legal moves (mate or stalemate) | `Legal moves: none`; recall is defined as 1 if the model also says none |
| Promotions and checks in SAN | python-chess SAN, including `=Q` and `+`/`#` |
| The model writes moves in a different order | `verify_legal_moves` compares sets |
| The model adds moves that don't exist | They lower precision; they are listed in `extra` |
| `--from-dataset` with a FEN that python-chess rejects | Exit 1, naming the line |

## Dependencies

python-chess, Unsloth, TRL, the RTX 5080 (models of 3–7B only, about 16 GB VRAM). The base weights are
re-downloaded from HuggingFace (deleted 2026-10-23), about 87 GB, against 143 GB free.

## Reproducibility

Seed 42 throughout. The dataset is a deterministic function of `board_dataset.jsonl`. A run record is
written to `runs/` for every model (F-7).

## Measuring criterion 0 (added 2026-10-24, before any results)

`fine-tuning/scripts/board_reading_test.py --task board+legal --config fine-tuning/config/finetune_config_legal.yaml`
runs the F-9 test on the 200 held-out positions for each base model and its `-board-legal-ft` version.

- **Prompts:** the "training" style uses the legal-moves training instruction. The "format" style adds a
  `Legal moves:` line with placeholders to the answer format.
- **Answer length:** `num_predict` is 700, because the legal-move list makes answers about 250 tokens
  longer.
- **Scoring:** each row also gets `legal_found`, `legal_recall` and `legal_precision` from
  `verify_legal_moves`, and the summary adds `mean_legal_recall` and `mean_legal_precision`.
- **Outputs:** `results/finetuning_experiment/board_legal_t0*.{jsonl,csv}`, so the pieces-only results
  are never overwritten.

Training's own per-epoch check keeps scoring the board part only, since the board comes first in
the target. `verify_export.py` scored only the board too, until 2026-10-29. It now also requires
held-out legal-move recall and precision ≥ 0.9, the criterion-0 bar (see `gguf-export-check.md`).

## Verification

- `fine-tuning/tests/test_legal_moves_dataset.py`:
  - the target's move set equals python-chess legal moves on sample and real FENs
  - sorted order, mate and stalemate give "none", and promotion SAN
  - `--from-dataset` keeps the order and FENs, so the held-out split is unchanged
  - `verify_legal_moves` recall and precision; the board parser ignores the legal line
- `tests/test_ft_run_setup.py` (extended): `config_legal_ft.yaml` matches the base re-run config apart
  from the models and paths; the suffixes resolve in the registry and the comparison
